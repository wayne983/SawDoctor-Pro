# 鋸寶 AI GitHub 測試站設計規格

**日期：** 2026-09-05  
**狀態：** 已確認設計，待依此實作  
**部署目標：** GitHub Pages 測試站；不修改既有 `SawDoctor-Pro` 首頁或舊 HAWER 官網。

## 1. 目標

建立獨立的「鋸寶 AI」單頁測試站，讓客戶可用自然語句描述材料、切割需求或困擾。畫面採藍白醫療感與鋸寶吉祥物對話框風格，提供初步導引、官網產品卡與官方 LINE 真人確認入口。

本階段的成功條件是：可在手機與桌面開啟、能輸入問題、可點選常用問題、能導向官網或 LINE，且不影響既有系統。

## 2. 範圍

### 本階段包含

- 獨立 GitHub Pages 路徑 `/zirbao-ai/`。
- 鋸寶入口、對話式介面、快速問題按鈕與回覆卡片。
- 規則式自然語句比對：材料、用途、外徑與常見困擾。
- 官網產品／服務導流卡，以及官方 LINE `@drhawer` 入口。
- 安全界線：裂紋、缺齒、明顯變形、劇烈震動、冒煙與火花，優先顯示停機與真人技師確認。
- 視覺素材先使用使用者提供圖像的品牌方向；正式公開前以已授權的透明吉祥物素材取代暫用版本。

### 本階段不包含

- 在前端放置任何 OpenAI 或其他模型 API 金鑰。
- 自動下單、保證規格適用、以單一症狀確診或取代真人技師。
- 寫入客戶資料、照片、Google Sheet 或 NAS。
- 變更現有 HAWER 舊官網後台。

## 3. 使用者流程

1. 客戶進入 `/zirbao-ai/`，看到鋸寶與「有鋸片問題？問鋸寶」入口。
2. 客戶點選快速問題或輸入文字。
3. 系統從受控產品／服務索引找出最多三個相關項目，顯示說明與官網連結。
4. 若資訊不足，回覆需補充的材料、尺寸、機台或現場條件，不做肯定規格承諾。
5. 若含安全關鍵字，顯示停機提醒，並提供診療系統與官方 LINE 真人確認。
6. 客戶可隨時點選「交給 LINE 鋸片醫生確認」。

## 4. 技術設計

- 純靜態 HTML、CSS、JavaScript，不需要建置工具或伺服器端。
- 以一個 `zirbao-ai/` 目錄交付，包含 `index.html`、`styles.css`、`app.js` 與測試檔。
- 索引資料與危險關鍵字置於前端受控常數；僅允許 HAWER HTTPS 網址。
- GitHub Pages 測試時以獨立路徑部署，後續可原封不動搬至 NAS。
- 真正生成式 AI 需另建安全後端，讓金鑰不會出現在 GitHub Pages 前端。

## 5. 視覺設計

- 主色：HAWER 深藍、亮藍、白與淺灰藍。
- 桌面：左側品牌／鋸寶引導，右側圓角對話窗。
- 手機：對話窗優先，鋸寶縮為頂部頭像與浮動裝飾。
- 對話框包含標題「鋸寶」、副標「鋸片醫生的 AI 小助手」、關閉控制、訊息泡泡、快速問題與輸入列。
- 以 CSS 圖形／文字建立第一版介面；不得將使用者提供的整張宣傳圖直接當成可互動 UI。

## 6. 回覆規則與安全

- 一般回覆使用「初步導引」語氣，明示實際選用仍須依材料、機台與現場條件確認。
- 資訊不足時至少補問材料、尺寸／厚度、機台或切割用途。
- 不從單一症狀直接下結論，不保證更換規格一定改善。
- 危險訊號只顯示停機檢查與真人技師確認的導流，避免產品推薦。

## 7. 驗證

- Node 自動測試：一般關鍵字、危險關鍵字、空白輸入、信任網址與 LINE 連結。
- 桌面與 390px 手機寬度：無水平捲軸、輸入與快速按鈕可操作。
- 本機預覽通過後，才推送 GitHub 並驗證 GitHub Pages 網址。

## 8. 後續正式版

測試確認後，將同一靜態網站部署到 NAS 的 HTTPS 網域；若要使用真正的生成式 AI，再新增受保護 API、內容索引更新流程與對話紀錄處理規則。
