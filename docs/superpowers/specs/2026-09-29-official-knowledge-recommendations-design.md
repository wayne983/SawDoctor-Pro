# 鋸片診療系統：官網知識推薦與欄位調整設計

日期：2026-09-29

## 目標

在不改變既有掛號、Email 與 LINE 流程的前提下，完成三項調整：

1. 「鋁用」機台設備廠商新增「勝榆」。
2. 初步診斷除了顯示可能適合的產品方向，也依客戶選擇的困擾與材料，顯示最多三篇相關的鋸片醫學誌、鋸片基因改造所或常見問題文章。
3. 將現有自由輸入的「目前鋸片品牌」欄位改標示為「鋸片品牌（自行填寫）」。

## 不在本次範圍

- 不從官網即時抓取或分析文章。
- 不讓文章推薦取代初步診斷或真人判讀。
- 不改變後端 `brand` 欄位名稱、掛號資料格式、試算表欄位或 Email 欄位。
- 不改變危險訊號的停機與人工問診優先順序。

## 使用者介面

### 機台設備廠商

「鋁用」設備品牌選單依序為：

`日意、鋒和、冠盛、和和、慶祥、合濟、中勝、昱帆、勝榆、其它`

欄位仍可留空；選擇「其它」時沿用既有自由輸入欄位。

### 鋸片品牌

保留現有文字輸入框及 `name="brand"`，只將標籤改為「鋸片品牌（自行填寫）」。欄位仍可留空。

### 推薦內容區

初步診斷右側／手機版診斷下方分成兩個獨立區塊：

1. 「可能適合的產品方向」：沿用現有產品推薦。
2. 「鋸片醫生延伸閱讀」：新增最多三篇官網內容。

每篇延伸閱讀顯示：

- 來源標籤：鋸片醫學誌、鋸片基因改造所或常見問題。
- 文章標題。
- 一句與本次困擾相關的閱讀理由。
- 「查看官網文章」按鈕，以新分頁開啟並使用 `rel="noopener"`。

若沒有適合文章，整個延伸閱讀區隱藏，不顯示空白卡片。

## 推薦資料模型

文章清單在前端以人工確認過的靜態資料維護，每筆至少包含：

```js
{
  id: 'flatness-runout',
  source: '鋸片醫學誌',
  title: '圓鋸片平面度與軸向端跳',
  url: 'https://www.hawer-knife.com/ProductDetails.asp?produid=240',
  issues: ['切割偏斜', '切割抖動', '噪音震動', '切面粗糙'],
  materials: [],
  reason: '了解鋸片平面度、端跳與機台精度如何影響切削穩定性。',
  priority: 90
}
```

`materials` 為空代表不限材料；有材料值時只在符合的材料中加分或顯示。文章推薦不依賴外部 API，也不在客戶瀏覽時抓取官網。

## 配對與排序規則

1. 以使用者勾選的所有困擾尋找候選文章。
2. 同一網址只保留一次。
3. 同時符合困擾與材料的文章優先。
4. 符合較多已選困擾的文章優先。
5. 再依人工設定的優先序排序，確保專題文章優先於一般 Q&A。
6. 最多顯示三篇。
7. 若使用者選擇「暫無困擾」，不顯示延伸閱讀。
8. 變更材料或困擾並重新評估時，必須重新計算且取代舊結果。

### 多重困擾範例

若選擇「毛邊多、黏屑塞齒」，材料為鋁合金，優先結果可為：

1. 鋸片老是塞鋁屑怎麼辦？
2. 關於鋸片切削不良
3. 鋁鑄棒切割更靜音，表面更平滑

不再增加第四篇，即使仍有其他候選文章。

## 危險狀況

- 危險診斷仍隱藏產品推薦，避免在停機情境中優先推銷產品。
- 延伸閱讀只保留能協助理解安全檢查的內容，並放在停機警示與官方 LINE 人工問診之後。
- 文章卡不得淡化既有的停機文字、砂輪機禁用警示或真人確認提示。
- 若無明確安全相關文章，可以完全不顯示延伸閱讀。

## 資料流與後端相容性

- `machineBrandsByType['鋁用']` 增加「勝榆」。
- `machineBrandLabel()`、掛號摘要、Email 及試算表沿用既有通用品牌處理，無後端欄位變更。
- `brand` 仍為自由文字，僅改顯示標籤。
- 新增純函式（名稱可於實作時調整）`getKnowledgeRecommendations(input)`，回傳不可變的文章陣列。
- 文章推薦只用於畫面顯示，不加入掛號 Email，以免初診單過長；使用者選擇的困擾與材料仍照既有流程寄送。

## 行動裝置與可及性

- 文章卡在手機版採單欄排列。
- 長標題與網址不得造成水平捲動。
- 每個連結需有可理解的文字，不只顯示「更多」。
- 延伸閱讀容器使用明確標題；動態更新後維持既有診斷區的閱讀起點，不另行搶走焦點。

## 測試與驗收

### 核心邏輯

- 「鋁用」廠商清單包含「勝榆」，其餘選項順序不變。
- 單一困擾能取得相關文章。
- 多重困擾能去除重複網址並最多回傳三篇。
- 材料專屬案例優先於一般文章。
- 「暫無困擾」回傳空陣列。
- 危險狀況不回傳產品推薦；延伸閱讀只允許安全相關候選。

### 畫面

- 標籤顯示「鋸片品牌（自行填寫）」，輸入仍寫入 `brand`。
- 有推薦時正確顯示來源、標題、理由及官網連結。
- 無推薦時隱藏延伸閱讀區。
- 重新初評後不殘留前一次文章。
- 手機寬度下文章卡不溢出，並位於簡易診斷之後。

### 回歸

- 既有核心、UI、後端與掛號測試全數通過。
- 成功掛號後仍顯示掛號號碼與官方 LINE 按鈕。
- Email 雙收件者、日期與掛號編號格式不變。

## 上架方式

實作完成並通過測試後，依既有 GitHub Pages 流程建立分支、提交、合併至 `main`，再確認正式網址載入新版內容。官網文章連結需逐一確認可開啟後才算完成。
